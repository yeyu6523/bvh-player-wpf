# 实现说明

## 1. 工程划分

`BvhPlayer.Core` 是不依赖界面的 .NET 类库，负责解析 BVH、计算关节姿态和管理播放时钟。`BvhPlayer.App` 使用 Windows WPF 和原生 `Viewport3D` 显示骨架，不依赖 Unity、OpenGL 插件或外部渲染库。

## 2. BVH 解析

`BvhDocument.Parser` 从文本中按需读取 token，支持制表符、换行、无空格大括号、UTF-8 BOM、带冒号的关节名和科学计数法数值。树按父节点先于子节点的顺序存储，每个关节包含：名称、父索引、OFFSET、通道数组和通道起始索引。End Site 作为无运动通道的末端节点存储。

运动数据读取为 `FrameCount × ChannelCount` 个有限数值，使用固定的区域无关格式解析，防止系统小数分隔符影响结果。严格检查数值数量、通道重复、未知通道、文件结构与正帧间隔。为避免失控内存分配，限制文件 256 MB、运动数值 6400 万个、关节 4096 个、层级深度 256 和单值绝对值 10¹²。

BVH 通常将 `CHANNELS` 放在 OFFSET 之后，本程序按这一标准层级结构读取。空或损坏文件会得到包含行号的错误信息。

## 3. 层级变换与通道顺序

对于列向量表示，局部矩阵为：

```text
Local = T(offset) × C1 × C2 × … × Cn
World = ParentWorld × Local
```

其中每个 C 都根据该节点 `CHANNELS` 中的声明顺序构造。C# `System.Numerics` 使用行向量约定，因此在代码中转置这一组合关系：先以 `T(offset)` 初始化，再依次左乘通道矩阵，最终得到 `Local × ParentWorld`。关节坐标为世界矩阵中的平移。

不能把所有文件都写死为 XYZ 或 ZXY 顺序。测试中包含非交换的 Z-X 旋转和父节点旋转后的子节点位置，还使用独立的 double 精度列向量矩阵实现，对实际样例的多个关键帧作数值核对。

## 4. 播放、暂停与速度

`PlaybackClock` 记录以秒为单位的播放位置，速度限制为 0.1–3.0。WPF 的渲染回调通过 `Stopwatch` 获取真实经过时间：

```text
Position += elapsedSeconds × Speed
FramePosition = Position / FrameTime
```

暂停不推进 Position，恢复播放从当前位置继续。停止回首帧，逐帧会暂停，拖动时间轴时先暂停并在完成拖动后按原状态继续。时间轴和 UI 显示使用 1 开始的帧号，内部帧索引从 0 开始。关掉循环后播放到最后一帧自动暂停；再次播放从首帧重新开始。

## 5. 平滑插值

将相邻帧各关节的局部矩阵分解为平移和四元数旋转，对平移执行 lerp，对旋转执行 slerp，然后按层级组合。这避免直接插值 350° 到 10° 时绕大圈。循环播放时最后一帧可插值到首帧；如果原始动作首尾不连续，接缝也可能不连续。可取消“平滑插值”检查原始离散帧。

## 6. 三维视图

关节使用共享球体网格，骨骼使用共享圆柱网格。材质和网格冻结，仅更新每个对象的变换，减少运行时几何分配。左侧骨骼为青色，右侧为暖橙色，中轴为浅色，选中关节为绿色。相机支持轨道旋转、缩放、平移与正交方向的透视观察。

载入时从最多 120 个分布帧估计动作包围盒，根据高度统一缩放，并将估计地面放在最小 Y 值下方。这里的地面是显示辅助，不是自动足底接触修正。锁定根节点水平位移仅影响显示；关闭后可观察原始空间路径。原始 BVH 与物理量保持不变。

## 7. 发布

使用 `.NET 10` 的 Windows x64 自包含单文件发布，将托管代码和 .NET 运行时打包进 exe，原生库由运行时在启动时解压到用户临时缓存。执行环境无需 Unity 或 .NET SDK，开发和重新编译需要 .NET 10 SDK。没有代码签名证书，因此 exe 没有发行者数字签名。
